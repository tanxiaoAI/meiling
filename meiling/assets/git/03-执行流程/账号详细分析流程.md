# 账号详细分析流程

## 1. 判断进入方式（内部）

先在当前对话中判断，之前是否已经读取过该账号的概要分析资料。

判断规则：

1. 如果当前对话已经读取过 `概要分析.md`，或者已经产出过该账号的概要分析结论，则按 `从概要进入` 处理
2. 如果当前对话没有读取过 `概要分析.md`，也没有现成的概要分析结论，则按 `直接进入详细` 处理

处理规则：

- `从概要进入`：承接当前对话里已经读取过的账号基础信息和概要分析结论，不重复读取已经明确的信息，只补本层新增材料
- `直接进入详细`：从 `账号库.csv`、对标账号目录和对标内容目录开始完整读取

## 2. 准备结果文件

本次详细分析只维护一个文件：

- `08-对标账号/<平台-账号ID-账号昵称>/详细分析.md`

后面的模式层、内容层、账号层、启发层，都写进这个文件。

## 3. 模式层

### 3.1 读取输入

如果当前进入方式是 `从概要进入`：

- 优先承接当前对话中已经读取过的账号基础信息
- 优先承接当前对话中已经读取过的概要分析结论
- 只补读本层新增材料

如果当前进入方式是 `直接进入详细`：

- 从零读取账号基础信息和本层材料

本层实际读取：

- `07-记录表/账号库.csv` 中该账号的基础字段
- `图片说明路径`
- `人工先验说明路径`

### 3.2 执行输入检查（内部）

检查：

- `图片说明` 是否存在、是否可用
- `人工先验说明` 是否存在、是否可用

### 3.3 缺资料处理

- `图片说明` 缺失：可以继续，但商品信息、主页呈现与转化线索判断都要写 `信息不足`
- `人工先验说明` 缺失：可以继续，但商业判断要写 `信息不足`

### 3.4 组装当前层 prompt

当前层 prompt 只组装这些输入：

- 账号基础信息：`账号ID`、`昵称`、`平台`、`简介`、`粉丝数`、`获赞数`、`标签`、`主页链接`
- 图片说明：商品或服务名称、价格、商品层级、交付形式、社群/课程/资料/线下课/顾问线索、主页昵称、主页简介、粉丝数/获赞数、封面风格、栏目感、主页整体气质
- 人工先验说明：原文整理内容

### 3.5 调用当前层 prompt

调用：

- `04-提示词/账号详细分析-模式层提示词.md`

生成模式层结果。

### 3.6 保存到详细分析.md

把模式层结果写入：

- `详细分析.md` 的 `模式层` 章节

### 3.7 在对话里向用户确认后进入下一层

在对话里问用户：

1. 是否认可当前模式层判断
2. 是否补充图片说明、私域、购买体验等信息
3. 是否进入内容层

## 4. 内容层

### 4.1 读取输入

如果当前进入方式是 `从概要进入`：

- 承接当前对话中已经读取过的账号基础信息和概要分析结论
- 本层重点补读内容层材料

如果当前进入方式是 `直接进入详细`：

- 从零读取内容层材料

本层默认读取：

- `内容列表路径`
- 全部 `09-对标内容/<内容ID>/原文案总结.md`
- 全部 `09-对标内容/<内容ID>/内容特征提取.md`

默认不读取：

- `视频文案.md`
- `内容分析无数据.md`
- `内容分析数据修正后.md`
- `修正对比.md`

### 4.2 执行输入检查（内部）

检查：

- `内容列表.csv` 是否存在、是否可用
- `原文案总结.md` 是否齐全
- `内容特征提取.md` 是否齐全

### 4.3 缺资料处理

- `内容列表.csv` 缺失：停止详细分析，先补 `内容列表.csv`
- `原文案总结.md` 不完整：可以继续，但内容层要写 `部分样本`
- `内容特征提取.md` 不完整：可以继续，但标签和机制判断要写 `部分样本`

### 4.4 组装当前层 prompt

当前层 prompt 只组装这些输入：

- 内容列表：`标题`、`媒介形式`、`点赞数`、`收藏数`、`评论数`、`分享数`、`核心互动数`、`数据水平`、`发布时间`、`发布时间区间`
- 全部 `原文案总结.md`
- 全部 `内容特征提取.md`

### 4.5 调用当前层 prompt

调用：

- `04-提示词/账号详细分析-内容层提示词.md`

生成内容层结果。

### 4.6 保存到详细分析.md

把内容层结果写入：

- `详细分析.md` 的 `内容层` 章节

### 4.7 在对话里向用户确认后进入下一层

在对话里问用户：

1. 是否认可当前内容层判断
2. 是否进入核验模式
3. 是否进入账号层

如果用户选择进入核验模式，再由系统按固定标准选样本补读：

- 优先选高表现样本
- 优先选结论冲突样本
- 优先选能代表不同媒介形式的样本

## 5. 账号层

### 5.1 读取输入

本层读取：

- `详细分析.md` 中已经完成的 `模式层`
- `详细分析.md` 中已经完成的 `内容层`

### 5.2 执行输入检查（内部）

检查：

- 模式层是否已完成
- 内容层是否已完成

### 5.3 缺资料处理

- 模式层未完成：停止，先补模式层
- 内容层未完成：停止，先补内容层

### 5.4 组装当前层 prompt

当前层 prompt 只组装：

- 模式层结果
- 内容层结果

### 5.5 调用当前层 prompt

调用：

- `04-提示词/账号详细分析-账号层提示词.md`

生成账号层结果。

### 5.6 保存到详细分析.md

把账号层结果写入：

- `详细分析.md` 的 `账号层` 章节

### 5.7 在对话里向用户确认后进入下一层

在对话里问用户：

1. 是否认可当前账号层判断
2. 是否需要修正理解
3. 是否进入启发层

## 6. 启发层

### 6.1 读取输入

本层读取：

- `详细分析.md` 中已经完成的 `模式层`
- `详细分析.md` 中已经完成的 `内容层`
- `详细分析.md` 中已经完成的 `账号层`
- `05-我方资料/我方当前概要.md`

### 6.2 执行输入检查（内部）

检查：

- 模式层是否已完成
- 内容层是否已完成
- 账号层是否已完成
- `我方当前概要.md` 是否存在、是否可用

### 6.3 缺资料处理

- 前三层任一未完成：停止，先补前一层
- `我方当前概要.md` 缺失：可以继续，但只输出通用启发

### 6.4 组装当前层 prompt

当前层 prompt 只组装：

- 模式层结果
- 内容层结果
- 账号层结果
- 我方当前概要

### 6.5 调用当前层 prompt

调用：

- `04-提示词/账号详细分析-启发层提示词.md`

生成启发层结果。

### 6.6 保存到详细分析.md

把启发层结果写入：

- `详细分析.md` 的 `启发层` 章节

### 6.7 在对话里向用户确认后结束

在对话里问用户：

1. 是否认可当前启发层结论
2. 是否补充我方约束或阶段信息
3. 是否结束本次详细分析

## 7. 回写账号库

完成后回写：

- `07-记录表/账号库.csv`

更新字段：

- `是否已详细分析` = 是
