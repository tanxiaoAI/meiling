# 内容生产流程

## 1. 判断本轮任务类型

先结合当前对话，判断本轮属于哪一种情况：

1. `从头生产`
   - 选题已经通过分析
   - 但还没有进入正式写稿
2. `承接上轮继续`
   - 当前已经完成前面某一步
   - 本轮在已有结果上继续向下推进
3. `局部重做`
   - 当前已有完整生产链路
   - 但用户只想重做其中某一部分，例如：
     - `生产前确认`
     - `内容框架`
     - `内容初稿`
     - `价值校准`
     - `终稿优化`

判断后，先在内部明确：

- 本轮对应的是哪个 `选题ID`
- 本轮从哪一步开始
- 本轮结束后要落到哪些文件

## 2. 读取标准规则

固定先读取：

- `05-我方资料/我方当前概要.md`

说明：

- 这一步的目标不是直接写稿，而是先明确我方当前阶段的账号方向、目标用户、产品服务、核心优势和现实约束
- 内容生产默认不再读取 `我方商业模式.md` 和 `我方自媒体模式.md`
- `我方当前概要.md` 就是本流程的统一压缩输入

## 3. 读取选题定稿

优先读取：

- `07-记录表/选题库.csv`

找到目标选题那一行，至少读取以下字段：

- `选题ID`
- `选题名称`
- `当前状态`
- `优先级`
- `是否建议做`
- `判断理由`
- `目标用户`
- `核心痛点`
- `收益承诺`
- `核心命题`
- `切口`
- `建议内容类别`
- `建议表达方向`
- `建议借用特征`
- `建议借用组合`
- `建议避开风险`
- `是否进入内容生产`
- `选题分析记录路径`
- `内容生产路径`

如果存在对应的 `选题分析记录路径`，再按需补读。

说明：

- 本流程默认承接 `选题分析流程` 的结构化结论
- 如果选题还没有形成稳定定稿，不进入本流程

## 4. 读取我方内容实例

优先读取：

- `07-记录表/我方内容库.csv`

检查当前 `选题ID` 是否已经对应某条 `我方内容ID`。

如果已经存在，则至少读取以下字段：

- `我方内容ID`
- `内容标题`
- `媒介形式`
- `目标平台`
- `当前状态`
- `内容框架路径`
- `内容初稿路径`
- `终稿路径`

如果不存在，则在内部准备创建一条新的我方内容记录。

说明：

- `选题库.csv` 管题目
- `07-记录表/我方内容库.csv` 管实际产出的内容
- 本流程正式进入写稿后，应以 `我方内容ID` 作为内容实例主键
## 5. 读取生产参考材料

按需读取：

- `02-业务方法论/内容特征词典.md`
- `07-记录表/内容特征库.csv` 中与当前题目相关的记录
- `07-记录表/内容特征组合库.csv` 中与当前题目相关的组合
- 必要时补读最相关的 1 到 3 篇对标内容的：
  - `内容特征提取.md`
  - `内容启发.md`

说明：

- 这里不是重新做对标内容分析
- 只读取能直接帮助当前生产的参考
- 优先读取与当前选题 `命题 / 切口 / 内容类别` 最接近的材料

## 6. 执行输入检查（内部）

按下面 4 项逐项检查：

1. `选题定稿是否稳定`
2. `我方当前方向是否清楚`
3. `是否有足够生产参考`
4. `是否允许进入写稿`

每项只检查 3 件事：

- `是否提供`
- `是否可用`
- `是否足以支撑本轮步骤`

最后判断：

- `当前最关键的信息缺口`
- `是否允许继续`

说明：

- 这一步是内部执行步骤，不属于最终交付内容

## 7. 缺资料时的处理规则

如果缺资料，按下面规则处理：

1. `是否建议做 != 是`
   - 停止本次内容生产
   - 先回到 `选题分析流程`
2. `是否进入内容生产 != 是`
   - 停止本次内容生产
   - 先让用户明确确认是否进入生产
3. `核心命题 / 切口 / 目标用户` 缺失
   - 不进入写稿
   - 先在对话中补齐
4. `生产参考材料` 缺失
   - 可以继续
   - 但在后续判断中明确说明“更多依赖当前题目定义，而非已有高置信参考”

如果检查结果中：

- `是否允许继续 = 否`
  - 直接在对话里告诉用户当前缺什么
  - 等待用户补资料
- `是否允许继续 = 是`
  - 才进入后续步骤

## 8. 生产前确认

### 8.1 读取输入

本步读取：

- `05-我方资料/我方当前概要.md`
- 当前选题的定稿信息
- 当前题目对应的生产参考材料

### 8.2 组装当前步判断

本步重点回答：

- 这次要写的是哪一条内容
- 这条内容最核心要服务谁
- 这条内容最重要的收益承诺是什么
- 这条内容最想让用户带走的判断是什么
- 这条内容优先借哪些特征与组合
- 这条内容最该避免什么错位

### 8.3 对话中确认

这一步必须和用户明确确认：

- `核心命题`
- `切口`
- `目标用户`
- `建议内容类别`
- `建议表达方向`

如果用户还想继续调整定义，就停留在本步，不进入下一步。

### 8.4 调用提示词

当本步结论已经稳定时，调用：

- `04-提示词/选题分析提示词.md`

说明：

- 这里不是重新做选题准入，而是把已确认的选题定义重新收束成稳定输入
- 目的是为后续 `内容框架生成` 提供统一、干净的上游定义

## 9. 生成内容框架

### 9.1 读取输入

本步读取：

- 已确认的生产前定义
- 相关参考特征与组合

### 9.2 组装当前步判断

本步重点回答：

- 这条内容最合适的整体结构是什么
- 开头应该如何进入
- 中段该按什么顺序推进
- 结尾该如何收束
- 哪些结构动作最值得借用

### 9.3 调用提示词

本步后续应调用对应的 `内容框架生成提示词`。

### 9.4 保存结果

保存到：

- `05-我方资料/我方内容/<我方内容ID>-<内容标题前10个字>/内容框架.md`

## 10. 生成内容初稿

### 10.1 读取输入

本步读取：

- `内容框架.md`
- 已确认的生产前定义
- 必要的参考特征

### 10.2 组装当前步判断

本步重点回答：

- 如何把框架展开成完整表达
- 如何让命题、切口和收益承诺真正落进正文
- 如何保证内容不是只有结构，而是真有信息和判断

### 10.3 调用提示词

本步后续应调用对应的 `内容初稿生成提示词`。

### 10.4 保存结果

保存到：

- `05-我方资料/我方内容/<我方内容ID>-<内容标题前10个字>/内容初稿.md`

## 11. 进行发布前价值校准

### 11.1 读取输入

本步读取：

- `内容初稿.md`
- 当前选题定稿信息
- 必要的参考特征与组合

### 11.2 组装当前步判断

本步重点回答：

- 这条内容有没有明确进入理由
- 这条内容有没有足够的持续价值
- 这条内容看完是否真的让用户获得东西
- 这条内容有没有形成记忆点、态度或动作闭环
- 这条内容是否存在空话、重复、弱命题、弱论证、价值不兑现的问题

### 11.3 对话中反馈

本步结果应直接告诉用户：

- 当前稿子最强的部分
- 当前稿子最需要改的 1 到 3 个问题
- 是否建议进入终稿优化

### 11.4 调用提示词

本步后续应调用：

- `04-提示词/发布前价值校准提示词.md`

## 12. 优化终稿

### 12.1 读取输入

本步读取：

- `内容初稿.md`
- `价值校准` 结论

### 12.2 组装当前步判断

本步重点回答：

- 哪些问题必须修改
- 哪些措辞需要更清楚、更有力、更贴近用户
- 哪些地方该删、该合并、该收束

### 12.3 调用提示词

本步后续应调用对应的 `终稿优化提示词`。

### 12.4 保存结果

保存到：

- `05-我方资料/我方内容/<我方内容ID>-<内容标题前10个字>/终稿.md`

## 13. 与用户确认是否结束生产

在本轮生产结束前，必须在对话里和用户明确确认：

- 当前终稿是否已经可用于拍摄或发布
- 是否还需要再回到上一步修改
- 是否现在就结束本轮内容生产

只有当用户明确表达类似下面意思时，才视为本轮生产完成：

- `可以用这个版本`
- `就按这个拍`
- `先定这个终稿`

如果用户还想继续调，就回到对应步骤，而不是擅自结束。

## 14. 整理本轮结构化摘要

在结束本轮前，先整理本轮结论，不要直接把整段对话记录当成结果。

固定整理为：

- `选题ID`
- `我方内容ID`
- `选题名称`
- `核心命题`
- `切口`
- `内容类别`
- `表达方向`
- `内容框架路径`
- `内容初稿路径`
- `终稿路径`
- `价值校准结论`
- `是否可拍摄发布`

## 15. 对话中反馈用户

完成本轮步骤后，在对话中单独告诉用户：

- 本轮完成到了哪一步
- 当前终稿是否已可用于拍摄或发布
- 如果后续进入发布后复盘，下一步要回写什么数据
- 如果发布后还要做内容验证，后续应进入 `03-执行流程/我方内容分析流程.md`

## 16. 回写选题库

完成后回写 `07-记录表/选题库.csv` 对应选题行的以下字段：

- `当前状态`
  - 建议写：`生产中` 或 `可拍摄`
- `内容生产路径`
  - 写入 `终稿.md` 路径或当前最新生产文件路径
- `备注`
  - 可补一句当前进度，例如：
    - `已完成内容框架`
    - `已完成内容初稿`
    - `已完成终稿优化`

如果当前终稿已经确认可拍摄或发布，也可以将：

- `当前状态` 更新为 `可拍摄`

## 17. 回写我方内容库

完成后同步回写 `07-记录表/我方内容库.csv` 对应内容行的以下字段：

- `我方内容ID`
  - 如果原本不存在，则自动生成
  - 建议格式：`我方内容001`
- `选题ID`
- `选题名称`
- `内容标题`
  - 默认可先与 `选题名称` 保持一致
  - 后续如标题单独调整，再更新
- `媒介形式`
- `当前状态`
  - 建议写：`生产中` 或 `可拍摄`
- `内容框架路径`
- `内容初稿路径`
- `终稿路径`
- `备注`

如果当前终稿已经确认可拍摄或发布，也可以将：

- `当前状态` 更新为 `可拍摄`

说明：

- `选题库.csv` 管“这个题是否值得做”
- `07-记录表/我方内容库.csv` 管“这个题最后实际产出了哪条内容”

## 18. 默认不在本流程内处理发布

本流程默认：

- 不负责拍摄
- 不负责上传
- 不负责平台发布

这些都由人工执行。

本流程只负责把内容生产到“可拍摄 / 可发布”的状态。
