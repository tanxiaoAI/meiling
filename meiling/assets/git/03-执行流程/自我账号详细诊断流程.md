# 自我账号详细诊断流程

## 1. 判断本轮任务类型

先结合当前对话，判断本轮详细诊断属于哪一种情况：

1. `新一轮诊断`
   - 当前对话还没有形成明确的自我账号诊断结论
   - 本轮需要从头开始校准当前账号
2. `承接上轮继续`
   - 当前对话已经完成了部分层级诊断
   - 本轮在已有结论上继续向下推进
3. `局部复诊`
   - 当前对话已经有完整或部分诊断结论
   - 用户只想重看某一个问题或某一层

判断后，先在内部明确：

- 本轮要诊断的是哪个账号
- 本轮重点诊断哪几层
- 本轮结束后预期要落到哪里：
  - 仅对话结论
  - 更新正式文档
  - 写入调整候选池

## 2. 读取标准答案

固定先读取：

- `05-我方资料/我方商业模式.md`
- `05-我方资料/我方自媒体模式.md`
- `02-业务方法论/自我账号诊断方法论.md`

如果存在，再读取：

- `05-我方资料/我方调整候选池.md`

说明：

- 这一步的目标不是读取更多信息，而是先明确“我原本想把这个号做成什么样”

## 3. 读取当前实际表现

优先读取与当前账号实际表现直接相关的材料。

固定先打开：

- `07-记录表/我方账号库.csv`

找到目标账号那一行，读取以下字段：

- `我方账号ID`
- `账号名称`
- `平台`
- `简介`
- `粉丝数`
- `获赞数`
- `标签`
- `主页链接`
- `主页资料路径`
- `图片说明路径`
- `经营数据路径`
- `用户反馈路径`
- `转化与承接信息路径`
- `默认内容索引路径`

如果存在，再读取：

- `主页资料路径`
- `图片说明路径` 对应目录
- `经营数据路径`
- `用户反馈路径`
- `转化与承接信息路径`

固定再打开：

- `07-记录表/我方内容库.csv`

优先读取与当前账号相关的05-我方资料/我方内容记录。

如果已经有05-我方资料/我方内容样本，再按需补读：

- 代表性内容对应的 `终稿.md`
- 代表性内容对应的 `内容特征提取.md`

说明：

- 自我账号详细诊断默认不要求一次拉齐经营数据
- 当前阶段先用05-我方资料/我方账号前台表现和已有内容材料判断“这个号有没有跑成我想要的样子”

## 4. 执行输入检查（内部）

按下面 5 项逐项检查：

1. `我方商业模式`
2. `我方自媒体模式`
3. `05-我方资料/我方账号主页资料与图片说明`
4. `05-我方资料/我方内容索引`
5. `代表性05-我方资料/我方内容样本`

每项只检查 3 件事：

- `是否提供`
- `是否可用`
- `是否足以支撑本轮判断`

最后判断：

- `当前最关键的信息缺口`
- `是否允许带缺口继续`

说明：

- 这一步是内部执行步骤，不属于最终交付内容

## 5. 缺资料时的处理规则

如果缺资料，按下面规则处理：

1. `我方商业模式.md` 缺失
   - 停止本次详细诊断
   - 先补 `我方商业模式.md`
2. `我方自媒体模式.md` 缺失
   - 停止本次详细诊断
   - 先补 `我方自媒体模式.md`
3. `主页资料或图片说明` 缺失或不可用
   - 可以继续
   - 但模式层中的产品承接、主页呈现判断要写 `信息不足`
4. `07-记录表/我方内容库.csv` 缺失或不可用
   - 停止本次详细诊断
   - 先补 `07-记录表/我方内容库.csv`
5. `代表性05-我方资料/我方内容样本` 缺失
   - 可以继续
   - 但内容层中的表达方式、吸引机制、信任机制判断要降低置信度

如果检查结果中：

- `是否允许带缺口继续 = 否`
  - 直接在对话框里告诉用户当前缺什么
  - 等待用户补资料
- `是否允许带缺口继续 = 是`
  - 那就带着缺口继续
  - 但在对应结论里明确写 `信息不足`

## 6. 模式层诊断

### 6.1 读取输入

本层读取：

- `05-我方资料/我方商业模式.md`
- 当前05-我方资料/我方账号基础信息
- `主页资料.md`
- 图片说明中的商品、服务、主页、承接线索
- `转化与承接信息.md` 中已有的前台承接判断

### 6.2 执行输入检查（内部）

检查：

- 当前账号是否存在清晰的前台承接线索
- 是否能判断当前内容最终在把用户引向什么
- 是否能判断当前目标付费用户和实际吸引人群之间的偏差

### 6.3 组装当前层判断

本层重点回答：

- 当前账号是否在服务正确的商业路径
- 当前承接的是不是我想卖的产品或服务
- 当前转化路径和我设想的一样吗
- 模式层最关键的偏差点是什么

### 6.4 在对话中输出并确认

先在对话中输出：

- 模式层一致的部分
- 模式层偏差最大的部分
- 当前最需要澄清的 1 到 3 个问题

然后向用户确认：

1. 是否认可当前模式层诊断
2. 是否补充产品承接、私域入口、真实成交线索
3. 是否进入账号层诊断

## 7. 账号层诊断

### 7.1 读取输入

本层读取：

- `05-我方资料/我方自媒体模式.md` 中的账号层标准
- 当前05-我方资料/我方账号主页资料
- 当前对外表达信息
- 已完成的模式层诊断结论

### 7.2 执行输入检查（内部）

检查：

- 账号定位是否可被当前主页信息支撑
- 当前用户会如何理解这个号
- 当前目标用户匹配度是否可判断

### 7.3 组装当前层判断

本层重点回答：

- 当前账号在用户心里到底被理解成什么
- 这和我想做的那个号一致吗
- 价值主张清不清楚
- 人设和差异化有没有跑偏
- 账号层最关键的偏差点是什么

### 7.4 在对话中输出并确认

先在对话中输出：

- 账号层一致的部分
- 账号层偏差最大的部分
- 当前最需要澄清的 1 到 3 个问题

然后向用户确认：

1. 是否认可当前账号层诊断
2. 是否补充主页表达、定位语、目标用户理解
3. 是否进入内容层诊断

## 8. 内容层诊断

### 8.1 读取输入

本层读取：

- `05-我方资料/我方自媒体模式.md` 中的内容层标准
- `07-记录表/我方内容库.csv`
- 代表性05-我方资料/我方内容样本
- 已完成的模式层诊断结论
- 已完成的账号层诊断结论

代表性内容样本优先选择：

1. 最近发布的内容
2. 最能代表当前主线的内容
3. 数据相对较高的内容
4. 明显跑偏的内容

### 8.2 执行输入检查（内部）

检查：

- 05-我方资料/我方内容索引是否足以看出当前主线
- 样本是否足以支持表达方式和吸引机制判断
- 是否能判断内容与商业连接之间的关系

### 8.3 组装当前层判断

本层重点回答：

- 当前内容主线是否符合既定设计
- 当前内容在讲对的问题吗
- 当前表达方式是否在把账号做成我想要的样子
- 当前吸引来的人对不对
- 当前信任建立和商业连接顺不顺
- 内容层最关键的偏差点是什么

### 8.4 在对话中输出并确认

先在对话中输出：

- 内容层一致的部分
- 内容层偏差最大的部分
- 当前最需要澄清的 1 到 3 个问题

然后向用户确认：

1. 是否认可当前内容层诊断
2. 是否补充某些代表性内容或样本
3. 是否进入收束阶段

## 9. 收束诊断结论

当模式层、账号层、内容层都完成后，先在内部整理一份本轮结构化摘要，固定包含：

- `本轮诊断目标`
- `模式层诊断结论`
- `账号层诊断结论`
- `内容层诊断结论`
- `当前最关键的 1 到 3 个问题`
- `优先调整建议`
- `哪些建议已足够明确`
- `哪些建议仍待确认`

说明：

- 这份结构化摘要默认作为对话中的内部收束材料
- 默认不单独保存成 `诊断报告.md`

## 10. 调用04-提示词

当本轮结构化摘要已经稳定后，调用：

- `04-提示词/自我账号详细诊断提示词.md`

输入来源为：

- `05-我方资料/我方商业模式.md`
- `05-我方资料/我方自媒体模式.md`
- 当前账号实际表现材料
- 已完成的模式层、账号层、内容层诊断结论
- 第9步整理出的结构化摘要

说明：

- 这一步的目标是把本轮多轮对话收束成稳定的详细诊断结论
- 不直接拿整段聊天记录去喂04-提示词

## 11. 与用户确认结果分流

在对话中明确和用户确认：

1. 哪些结论已经足够明确，可以直接采用
2. 哪些只是候选方向，暂时不正式采用
3. 本轮是否需要立即修改正式文档

分流规则：

- `已确认采用`
  - 直接更新：
    - `05-我方资料/我方商业模式.md`
    - `05-我方资料/我方自媒体模式.md`
- `尚未确认`
  - 写入：
    - `05-我方资料/我方调整候选池.md`

## 12. 默认不生成正式诊断报告

自我账号详细诊断默认：

- 不额外生成 `详细诊断.md`
- 不额外生成 `诊断报告.md`

只有在下面场景，才考虑单独产出报告：

- 用户明确要求归档
- 需要同步给合伙人或团队
- 需要阶段性复盘留档
