# 数据分析方法论

## 1. 文档目标

本方法论文档用于定义“如何理解和使用数据来判断内容与账号表现”。

这里说的数据分析，不是单纯看哪条内容点赞高、哪条内容播放低，也不是只做结果排名，而是回答下面这些问题：

- 这些数据分别代表什么
- 这些数据主要对应用户链路中的哪个环节
- 哪些数据可以支持判断，哪些数据不能过度解释
- 什么叫内容本身成立，什么叫只是被平台放大
- 什么叫内容本身没成立，什么叫只是没有被放大
- 数据进入后，原本的内容判断应该如何被修正
- 在复盘时，数据应该如何与选题、脚本、特征、结果连接起来

这份方法论的主要用途有四类：

- 为 `内容分析数据修正后` 和 `修正对比` 提供上位判断边界
- 为 `发布后复盘流程` 提供数据判断规则
- 为后续的 `自我账号完整诊断 / 账号经营体检` 提供统一数据口径
- 为后续的内容特征验证、组合验证和我方验证提供事实基础

需要明确：

- 数据分析不是独立于业务和内容的纯表格动作
- 数据分析的目标不是替代判断，而是约束判断、修正判断、验证判断

## 2. 分析原则

- 先明确对象，后看数据：先明确这次分析的是单篇内容、选题、账号局部，还是阶段经营表现
- 指标要归类：每个数据都要先明确它主要对应 `进入 / 持续 / 获得 / 沉淀 / 转化` 的哪一段
- 数据不等于质量：高数据不自动等于高质量，低数据也不自动等于内容没有价值
- 数据不自动等于原因：数据只能提示问题位置，不能直接替代归因
- 先看相对关系，后看绝对值：同一账号、同一时期、同类内容之间的比较，比单个绝对值更有意义
- 区分内容问题和放大问题：内容本身没成立，和内容成立但没被平台放大，是两回事
- 指标要看组合，不看孤点：单个指标容易误导，多个指标联动才能支撑更稳的判断
- 数据结论要有边界：没有足够数据时，只能下弱结论，不能硬推强结论

## 3. 核心逻辑

数据分析的核心逻辑如下：

- 先明确本次要回答什么问题
- 再确认这次可用的数据有哪些
- 再把数据映射到用户链路上
- 再判断每一段链路是强、弱，还是存在明显缺口
- 再把数据结果与内容判断、选题判断、复盘判断连接起来
- 最后输出“哪些判断被验证、哪些判断被推翻、哪些地方仍然不能下结论”

如果压成一句话，就是：

- `数据分析不是直接给答案，而是把结果信号映射回用户链路，再约束内容与业务判断。`

## 4. 核心要素

### 4.1 总览

| 要素 | 核心问题 | 作用 |
| --- | --- | --- |
| 分析对象 | 这次到底在分析什么 | 先定口径 |
| 指标分类 | 每个指标主要对应哪一段用户链路 | 防止乱看数 |
| 数据层级 | 不同层级的数据能支撑什么判断 | 防止越级解释 |
| 判断边界 | 哪些结论可以下，哪些不能下 | 防止过度归因 |
| 修正规则 | 数据进入后，原本判断如何升级、降级或推翻 | 让分析更稳 |

### 4.2 分析对象

这一部分解决的是：

- 本次分析的数据，到底服务哪个对象

建议先区分四类对象：

| 对象 | 核心问题 | 常见场景 |
| --- | --- | --- |
| 单篇内容 | 这条内容表现如何 | 内容分析第二轮、发布后复盘 |
| 一组内容 | 某一组题材或风格表现如何 | 内容特征汇总、组间对比 |
| 单个选题 | 这个题是否值得继续做 | 发布后选题复盘 |
| 阶段经营表现 | 一段时间的账号经营是否健康 | 自我账号完整诊断、经营体检 |

需要明确：

- 先定对象，再定指标口径
- 不能拿“阶段经营数据”去直接评价一条内容，也不能拿“单篇数据”去直接盖棺整个账号

### 4.3 指标分类

这一部分解决的是：

- 每个指标主要对应用户链路中的哪一段

建议统一按下面五段理解：

| 链路 | 核心问题 | 常见指标 |
| --- | --- | --- |
| 进入 | 用户会不会点开、停下来、进入消费 | 播放、浏览、点击、首屏停留、打开率相关信号 |
| 持续 | 用户会不会继续看下去 | 完播、完读、平均停留、流失位置、跳出相关信号 |
| 获得 | 用户会不会觉得值 | 收藏、转发、评论质量、停留深度、二次阅读 |
| 沉淀 | 用户会不会留下记忆、态度或轻动作 | 关注、评论参与、收藏、转发、私信 |
| 转化 | 用户会不会进入更强业务动作 | 加微信、咨询、表单、成交、线索 |

需要明确：

- 同一个指标可能同时对多个环节有参考意义，但必须先确定它的主要作用
- 例如：
  - `收藏` 更主要对应 `获得`
  - `关注` 更主要对应 `沉淀`
  - `私信 / 咨询 / 成交` 更主要对应 `转化`

### 4.4 数据层级

这一部分解决的是：

- 不同数据能支撑多强的判断

建议统一按下面三层理解：

| 层级 | 定义 | 能支撑的判断 |
| --- | --- | --- |
| 基础互动层 | 播放、浏览、点赞、评论、收藏、转发 | 主要支撑内容在用户链路上的表层表现判断 |
| 深度反馈层 | 评论质量、私信内容、用户反馈、截图整理 | 主要支撑用户真实获得感与沉淀判断 |
| 业务结果层 | 加微信、表单、咨询、成交、线索 | 主要支撑转化与商业承接判断 |

需要明确：

- 只有基础互动层时，可以判断“内容表现”，但不能强判“业务转化”
- 只有业务结果层时，也不能倒推“内容每一层都做得好”
- 层级越高，能支撑的业务结论越强，但样本通常越少

## 5. 判断边界

数据分析最容易出错的地方，不是不会看数，而是过度解释。

建议固定遵守下面这些边界：

- `高播放` 只说明进入更可能成立，不自动说明内容整体都好
- `高点赞` 只说明即时反应较强，不自动说明用户真的获得了深价值
- `高收藏 / 高转发` 更能说明内容有获得感，但仍不自动等于商业价值
- `高评论` 要先看评论质量，不能只看数量
- `低数据` 不自动说明内容无价值，要先看发布时间、平台放大、样本对比和选题类型
- `有成交` 不自动说明内容本身强，也可能是用户本来就有信任基础
- `没成交` 不自动说明内容失败，也可能只是内容承担的任务不是直接转化

一句话说：

- `数据能说明结果信号，但不能脱离内容任务和业务链路单独下结论。`

## 6. 修正规则

这一部分解决的是：

- 数据进入后，原本的内容判断该如何调整

建议统一分成四类结果：

| 结果 | 定义 | 处理方式 |
| --- | --- | --- |
| 被验证 | 原本判断和数据表现一致 | 保留原判断 |
| 被修正 | 原本方向基本对，但强弱度需要调整 | 升级或降级判断 |
| 被推翻 | 原本核心判断与数据明显冲突 | 改写原判断 |
| 暂不确定 | 数据不足或结果混杂，暂时不能下结论 | 保留边界，不硬判 |

修正时建议重点回答：

- 哪些原判断被数据支持
- 哪些原判断被高估了
- 哪些原判断被低估了
- 哪些判断原本就证据不足

需要明确：

- 修正的目标不是证明第一轮对不对
- 修正的目标是让结论更接近真实

## 7. 常见归因框架

数据进入后，复盘时建议优先沿着下面 4 个方向归因：

| 归因方向 | 核心问题 | 常见表现 |
| --- | --- | --- |
| 选题判断 | 题本身值不值得用户进入 | 进入弱、痛点弱、切口弱、题意不清 |
| 内容兑现 | 进来了以后值不值 | 持续弱、获得弱、命题弱、结构弱、价值不兑现 |
| 平台放大 | 内容本身成立，但没有被充分放大 | 内容表现不差，但起量弱或分发弱 |
| 商业承接 | 内容有沉淀，但后续动作没承接起来 | 私信少、加微信少、成交弱、链路断裂 |

需要明确：

- 复盘时不要一看到数据差就说“内容不行”
- 也不要一看到数据好就说“模式成立”
- 先判断问题主要卡在哪一段，再决定下一步改什么

## 8. 标准分析顺序

讨论一组数据时，建议按下面顺序推进：

| 步骤 | 目标 | 输出 |
| --- | --- | --- |
| 1. 先定分析对象 | 明确这次分析的是单篇、题组、选题还是阶段经营 | 对象定义 |
| 2. 盘点可用数据 | 明确当前有哪些数据、缺哪些数据 | 数据清单 |
| 3. 映射到用户链路 | 判断进入、持续、获得、沉淀、转化分别如何 | 链路判断 |
| 4. 判断数据层级 | 判断当前数据足不足以支撑强结论 | 结论边界 |
| 5. 与原判断对照 | 看哪些被验证、哪些被修正、哪些被推翻 | 修正结果 |
| 6. 做归因判断 | 识别主要问题更偏选题、内容、放大还是承接 | 归因结果 |
| 7. 输出调整建议 | 明确下一步该改什么、先改什么 | 调整建议 |

一句话说：

- `数据分析的顺序是：先定对象，再盘数据，再映射链路，再做修正和归因。`

- 复盘回答的是 `这次为什么会这样、该怎么调整`

## 10. 一句话收束

数据分析方法论最终要解决的，不是“哪条数据高一点、低一点”，而是：

- `把结果信号映射回用户链路，明确这些数据究竟支持什么判断、不能支持什么判断，并用它来修正内容和业务判断。`
