# 内容初稿生成04-提示词

你的任务是根据已确认的内容框架，生成一版可进入价值校准的内容初稿。

## 写作原则

- 以 `内容框架.md` 为主，不擅自偏离原本结构
- 初稿的目标是把框架展开成完整表达，不是追求一次成完美终稿
- 重点保证：命题清楚、信息有增量、表达可读、结构顺畅
- 不要把每一段都写得很满，保留后续优化空间
- 不要为了显得高级而牺牲清晰度
- 不要只写观点口号，必须让用户真的获得信息、判断或方法

## 输出要求

- 直接输出正式正文，不写解释性前言
- 不写“以下是初稿”“供参考”
- 不复述04-提示词
- 不输出大纲或解释
- 结果用于直接保存到 `内容初稿.md`

## 输出结构

按已提供框架的顺序直接展开。

同时必须满足下面要求：

## 1. 开头要求

- 开头尽快进入问题，不要铺垫过长
- 前两段必须让用户知道：
  - 这条内容和我有什么关系
  - 我为什么值得继续看

## 2. 主体要求

- 每一段都必须推进，不要只是重复前文
- 如果是观点型，要给出清楚判断和支撑
- 如果是教程型，要给出可理解的步骤或方法
- 如果是案例型，要写清关键情境、判断与结果
- 如果是混合型，要保持主次清楚，不要打架

## 3. 命题要求

- 全文必须稳定服务同一个核心命题
- 不要中途换命题
- 不要为了丰富显得什么都讲一点

## 4. 表达要求

- 优先清楚、直接、自然
- 少写空泛的“大道理”
- 避免明显的 AI 式堆砌和重复解释
- 如需增强力度，优先靠判断和例子，不靠情绪硬拉

## 5. 结尾要求

- 结尾要把全文收住
- 先完成判断闭环，再决定是否加动作引导
- 如果需要动作引导，要自然，不要突然索取感过强

## 6. 自检要求

生成前在内部自检：

- 命题是否清楚
- 切口是否稳定
- 结构是否顺
- 是否真的有获得感
- 是否存在空话、重复、注水

如果存在明显问题，先在内部修正再输出。
