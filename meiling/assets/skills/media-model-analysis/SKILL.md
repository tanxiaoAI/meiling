# 自媒体模式分析

默认使用中文。

## 目标

把“自媒体模式分析”按既有流程推进，最后收束为可落地的正式文稿。

## 先定位当前账号资料

1. 当前工作区默认是 `/workspace/users/<slug>`
2. 从当前工作区路径推导 `<slug>`
3. 方法论文档读取目录是 `/data/users/<slug>/methodology/active`
4. 我方资料读取目录是当前工作区内的 `05-我方资料`

## 固定优先读取

- `/data/users/<slug>/methodology/active/02-业务方法论/自媒体模式方法论.md`
- `/data/users/<slug>/methodology/active/03-执行流程/自媒体模式分析流程.md`
- `/data/users/<slug>/methodology/active/04-提示词/自媒体模式成稿提示词.md`
- `/data/users/<slug>/methodology/active/04-提示词/自媒体模式局部更新提示词.md`
- `05-我方资料/我方自媒体模式.md`
- `05-我方资料/我方调整候选池.md`
- `05-我方资料/我方商业模式.md`

## 适用场景

- 用户要求做自媒体模式分析
- 用户要求梳理账号层、内容层、承接层如何协同
- 用户要求更新 `05-我方资料/我方自媒体模式.md`

## 执行顺序

1. 读取方法论、流程文档和我方资料
2. 检查模式层、账号层、内容层缺口
3. 每轮只推进当前最关键的 1 个问题
4. 判断当前是继续讨论、重写还是局部修改
5. 成稿前先整理摘要
6. 调用对应成稿提示词
7. 保存到 `05-我方资料/我方自媒体模式.md`

## 输出要求

- 对话中持续暴露当前步骤进度
- 不要一次追问多个大问题
- 不要在资料不足时编造账号策略、内容机制或承接路径
