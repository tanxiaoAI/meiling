# 内容分析方法论

## 1. 文档目标

本方法论文档定义单篇内容的分析边界、拆解框架、判断顺序与特征沉淀方式。

适用对象：`对标内容`、`我方已产出的内容`。

## 2. 分析原则

- 先内容本身，后看数据：先判断这篇内容原本是怎么成立的，再用数据修正，不一开始就被数据牵着走
- 表现先行，逆向推导：先看用户最终看到什么，再反推动作、机制、策略和内核
- 逆推之后，必须正向校验：反推出内核后，再检查这个内核能否正向解释策略、机制、动作和表现的一致性
- 分层判断：内核层、策略层、机制层、动作层、表现层各自解决不同问题，不混用边界
- 类别先判定：先判断这篇内容主要属于什么内容类别，再分析它的结构和有效性
- 用户验收优先：内容质量不是作者自嗨，而是用户是否愿意进入、持续、获得、沉淀
- 质量与数据分开：数据是事后验证，不等于质量本身；高数据不一定质量高，低数据也不一定内容无价值
- 特征要可复用：单篇分析最终要沉淀成可迁移、可汇总、可反作用于生产的特征卡

## 3. 核心逻辑

- 先看表现层：用户最终看到什么
- 再拆动作层：这篇内容具体用了哪些写法和结构
- 再解释机制层：这些写法为什么能吸引、留住、推动用户
- 再判断策略层：这篇内容是用什么内容类别、媒介形式和主目标侧重来交付价值
- 最后反推内核层：这篇内容到底写给谁、解决什么问题、承诺什么收益、想让用户相信什么
- 反推完成后，再正向检查：内核层是否真的能推出当前的策略、机制、动作和表现
- 在无数据判断之后，再结合数据做修正
- 最后比较修正前后差异，并沉淀出可复用特征
- `内容分析从最终表现逆向拆回内容内核，再正向校验各层一致性，并用数据验证哪些判断真正成立。`

## 4. 核心要素

### 4.1 总览

| 要素     | 核心问题                      | 作用          |
| ------ | ------------------------- | ----------- |
| 内容层级   | 这篇内容在内核、策略、机制、动作、表现上分别是什么 | 建立完整分析骨架    |
| 用户验收链路 | 用户会不会进入、持续、获得、沉淀          | 定义内容质量的检验路径 |
| 外部参照   | 这篇内容在账号基础和平台环境中表现如何       | 给数据修正提供稳定边界 |
| 数据修正   | 数据出来后，哪些判断被验证，哪些判断需要修正    | 防止只靠主观判断    |
| 内容特征提取 | 这篇内容最终有哪些可复用特征            | 让单篇分析进入资产沉淀 |

### 4.2 内容层级

按下面五层理解：

| 层级  | 核心问题                   | 包含字段                       | 作用        |
| --- | ---------------------- | -------------------------- | --------- |
| 内核层 | 这篇内容到底要讲什么、为谁而讲、为什么值得看 | 目标受众、核心痛点、收益承诺、核心命题、主题、切口  | 定义内容的根    |
| 策略层 | 这篇内容准备用什么路径交付价值        | 媒介形式、内容类别、主目标侧重            | 定义内容的打法   |
| 机制层 | 这篇内容为什么能吸引、留住、促成内容内沉淀  | 捕获注意力、维持注意力、沉淀与行动触发        | 定义内容有效的原因 |
| 动作层 | 这篇内容具体用了哪些写法           | 标题、封面、开头、内容结构、结尾、表达风格、互动设计 | 定义内容的具体手法 |
| 表现层 | 用户最终看到的是什么             | 标题文本、正文文本、封面/画面、剪辑/版式      | 定义内容的最终外观 |

### 4.3 内核层

包含六个字段：

| 字段   | 定义        | 回答的问题        | 依赖关系           |
| ---- | --------- | ------------ | -------------- |
| 目标受众 | 写给谁       | 这篇是给谁看的      | 决定痛点、收益承诺和表达方式 |
| 核心痛点 | 解决什么问题    | 这篇主要解决什么问题   | 来自目标受众         |
| 收益承诺 | 给用户什么结果   | 为什么值得用户看     | 来自痛点，支撑捕获机制    |
| 核心命题 | 最终让用户相信什么 | 这篇最后想让用户相信什么 | 由主题和切口收束而成     |
| 主题   | 讲什么领域     | 这篇在讲哪类事      | 最上位背景，决定切口范围   |
| 切口   | 从哪里切入     | 这篇从哪个角度切进去   | 受主题约束，服务命题表达   |

两组关键关系：

#### 1. 主题、切口、命题

- `主题`：这篇内容在讨论的哪一片问题域
- `切口`：这篇内容从哪个角度切进去
- `命题`：这篇内容最核心想让用户接受的判断或结论
- 主题决定讲哪片山
- 切口决定从哪儿下刀
- 命题决定最终落点

#### 2. 命题和收益承诺

- `收益承诺`：对用户说“你能得到什么”
- `核心命题`：对用户说“真正的问题是什么、正确理解是什么”
- 收益承诺是用户层面的结果
- 核心命题是作者层面的判断

### 4.4 策略层

包含三个字段：

| 字段    | 定义              | 例子                               |
| ----- | --------------- | -------------------------------- |
| 媒介形式  | 内容通过什么媒介呈现      | 图文、视频口播、录屏讲解、直播切片、对话访谈、Vlog 等    |
| 内容类别  | 内容主要用什么价值交付方式成立 | 教程型、观点型、资料型、案例型、复盘型、清单型、故事型、混合型等 |
| 主目标侧重 | 这篇内容当前更主要承担什么职责 | 流量、涨粉、交易                         |

- `这篇内容用什么媒介形式、内容类别和主目标侧重来兑现内核层的价值`

#### 4.4.1 内容类别

- `内容类别` 就是这篇内容的主要价值交付类别
- 它本质上属于 `策略层`
- 不再把 `观点型 / 教程型 / 资料型` 这类标签叫做 `内容类型`

优先判断下面几类：

| 类别  | 定义                   | 典型特征              | 价值兑现标准        |
| --- | -------------------- | ----------------- | ------------- |
| 教程型 | 以传授具体方法、操作步骤为核心目标    | 有明确步骤、流程、工具、模板    | 用户能否按步骤复现     |
| 观点型 | 以输出判断、立场、认知框架为核心目标   | 有核心观点、论证逻辑、案例支撑   | 用户是否获得新的认知视角  |
| 资料型 | 以提供信息、规则、数据为核心目标     | 信息密度高、有权威背书、可保存备查 | 信息是否稀缺且准确     |
| 案例型 | 以分享经验、复盘过程为核心目标      | 有时间线、决策点、结果数据     | 案例是否有启发性和可信度  |
| 复盘型 | 以回顾过程、总结得失、沉淀判断为核心目标 | 有过程回看、关键选择、阶段结论   | 用户是否能看见思路升级   |
| 清单型 | 以盘点资源、步骤、要点为核心目标     | 条目清晰、便于保存、便于检索    | 用户是否能快速提取可用信息 |
| 故事型 | 以叙事推进认知或情绪为核心目标      | 情境、转折、人物、结果       | 用户是否被带入并记住结论  |
| 混合型 | 同时包含 2 种及以上类别特征      | 例如“以观点型为主，辅以案例支撑” | 主次关系是否清晰      |

- `这篇内容到底在用什么方式向用户兑现价值`

#### 4.4.2 主目标侧重

只写一个主目标侧重：

- `流量`：优先追求进入效率和分发扩张
- `涨粉`：优先追求认知沉淀、关注和长期关系
- `交易`：优先追求信任建立、筛选用户和后续动作
- `主目标侧重` 不是说其他目标不重要
- 它只是帮助分析时判断这篇内容的评价重心应该放在哪

### 4.5 机制层

统一分为三段：

| 机制      | 核心作用             | 核心问题                     |
| ------- | ---------------- | ------------------------ |
| 捕获注意力   | 让用户愿意进入          | 怎么让用户点开或停下来              |
| 维持注意力   | 让用户愿意看下去         | 怎么让用户持续消费并觉得有关、有值、可信     |
| 沉淀与行动触发 | 让用户留下记忆、态度或内容内动作 | 怎么让用户留下收藏、评论、关注、私信等内容内动作 |

#### 1. 捕获注意力

常见触发：

- 认知触发：反常识、信息缺口、意外感
- 功利承诺：结果、方法、避坑、效率、清单
- 情绪触发：共鸣、焦虑、愤怒、希望
- 社会触发：身份、群体、权威、社会证明

#### 2. 维持注意力

常见支点：

- 建立相关性：不断让用户确认“这说的是我”
- 持续交付价值：每一段都有信息增量
- 累积信任感：不是只会说，而是能让用户相信

#### 3. 沉淀与行动触发

常见方式：

- 抬升动机：让用户觉得这个动作值得做
- 降低摩擦：让动作更容易完成
- 明确触发：在对的时机把动作点出来
- AIDA 对应的是：Attention -> 捕获，Interest/Desire -> 维持，Action -> 沉淀与行动触发
- Fogg Behavior Model 对应的是：Motivation -> 动机，Ability -> 摩擦，Prompt -> 提示
- 这里讨论的是 `内容内动作`
- `咨询 / 加微信 / 成交` 这类业务动作属于更后面的承接问题，不直接等于单篇内容质量本体

### 4.6 动作层

包含下面字段：

| 字段   | 主要服务的机制        | 回答的问题          |
| ---- | -------------- | -------------- |
| 标题   | 捕获注意力          | 怎么吸引点开         |
| 封面   | 捕获注意力          | 怎么吸引点开         |
| 开头   | 捕获注意力 + 维持起点   | 怎么把用户拉进来       |
| 内容结构 | 维持注意力          | 怎么把内容顺着讲下去     |
| 结尾   | 维持收束 + 沉淀与行动触发 | 怎么完成闭环或推动内容内动作 |
| 表达风格 | 主要影响信任感        | 用户如何感受到“你”     |
| 互动设计 | 主要服务沉淀与行动触发    | 怎么推动用户参与或行动    |

### 4.7 表现层

包含下面字段：

| 字段    | 定义                  | 回答的问题           |
| ----- | ------------------- | --------------- |
| 标题文本  | 最终呈现出来的标题句子         | 用户看到的标题是什么      |
| 正文文本  | 最终呈现出来的主体内容         | 用户实际读到或听到的正文是什么 |
| 封面/画面 | 图文封面、视频封面、视觉元素      | 用户第一眼看到的视觉呈现是什么 |
| 剪辑/版式 | 视频节奏、字幕、图文排版、视觉组织方式 | 用户在消费时的体验长什么样   |

## 5. 内容质量

- 用户会不会进入
- 用户会不会继续
- 用户会不会觉得值
- 用户会不会留下认知、情绪或动作

### 5.1 内容质量定义

内容质量 = 内容在用户验收链路上的整体完成度

拆成两部分：

- `价值选择质量`：内核层是否选对了人、问题、切口、收益和命题
- `价值交付质量`：策略层、机制层、动作层是否真的把价值传递出去

### 5.2 用户验收链路

按四个连续关卡判断：

| 关卡 | 核心问题          |
| -- | ------------- |
| 进入 | 有没有让人愿意进入     |
| 持续 | 有没有让人愿意继续消费   |
| 获得 | 有没有让人觉得真的值    |
| 沉淀 | 有没有留下认知、情绪或动作 |

### 5.3 主因与次因

内容质量的主要决定因素：

- 选题与内核匹配：是否击中明确人群的真实兴趣、痛点、欲望或身份认同
- 价值兑现质量：是否真的给出新信息、新判断、新方法或强情绪满足
- 清晰度与结构：信息是否容易理解、推进是否顺、有没有认知负担
- 进入效率：标题、封面、开头是否快速把价值翻译成可感知信号

次级放大因素：

- 信任增强：案例、证据、经验、真实性
- 风格与情绪包装：幽默、犀利、故事感、强观点、代入感
- 互动设计：评论、收藏、关注、私信等内容内动作设计
- 转化设计：业务动作承接
- 转化设计属于业务放大器，不等于内容质量本体

## 6. 数据修正

- 数据是事后验证，不是内容质量本身
- 数据高，不等于内容所有层都做得好
- 数据低，也不等于内容没有价值

数据修正有三类作用：

- 验证原本判断是否站得住
- 发现原本主观分析里的误判
- 区分“内容本身有问题”与“内容成立但没被放大”

### 6.1 修正参照系

数据修正固定参考两类外部变量：

#### 1. 账号基础参照

优先看两个字段：

- `粉丝数`：用来判断当前互动量对这个体量的账号来说是高还是低
- `历史平均表现`：默认用同账号、同平台、同媒介形式最近 `20` 条内容的 `核心互动数中位数` 作为操作口径；如果不足 `10` 条，就不强行计算

获取方式：

- `粉丝数`：来自 `账号库.csv`、主页资料或账号分析材料
- `历史平均表现`：来自 `内容列表.csv` 或 `内容库.csv`，按最近样本自行计算
- `历史平均表现` 这里虽然叫“平均”，但执行时建议用 `中位数`，避免被单条爆款拉歪

#### 2. 平台参照

固定参考三个平台：

- `小红书`
- `抖音`
- `B站`
- 平台参照主要解决的是“同样 1 万互动，在不同平台含义并不一样”
- 平台参照只用来提供稳定基线，不引入发布时间、节假日、热点偶发性这类高噪音变量

### 6.2 数据水平初判

如果当前只有基础互动数据，先基于 `核心互动数 = 点赞数 + 收藏数 + 评论数` 做平台级初判。

当前基线：

| 平台  | 大爆款        | 小爆款           | 优秀          | 正常         | 差       |
| --- | ---------- | ------------- | ----------- | ---------- | ------- |
| 小红书 | `>= 10000` | `3000-9999`   | `1000-2999` | `300-999`  | `< 300` |
| 抖音  | `>= 30000` | `10000-29999` | `3000-9999` | `800-2999` | `< 800` |
| B站  | `>= 5000`  | `2000-4999`   | `800-1999`  | `200-799`  | `< 200` |

- 这是一套 `平台基础阈值`，作用是先把数据放进一个大致分层
- 这套阈值不是绝对真理，后续可以随着样本积累继续校准

### 6.3 相对校正

平台基础阈值之后，再根据账号基础做相对校正。

按下面规则执行：

- 如果当前内容的 `核心互动数 >= 历史平均表现中位数的 3 倍`，可上调 `1` 档
- 如果当前内容的 `核心互动数` 处于 `历史平均表现中位数的 1.5-3 倍`，可标记为 `相对偏强`
- 如果当前内容的 `核心互动数 <= 历史平均表现中位数的 0.5 倍`，可下调 `1` 档
- 如果缺少足够历史样本，就只保留平台基础阈值，不强行做相对校正
- 相对校正只在有足够历史样本时使用，没有样本就只保留平台基础阈值

### 6.4 修正时重点观察

修正时重点观察：

- 进入是否成立：点击、播放起量、打开率相关信号
- 持续是否成立：完读、完播、停留、流失相关信号
- 获得是否成立：收藏、转发、评论质量、停留深度
- 沉淀是否成立：关注、私信、二次传播等内容内沉淀信号

## 7. 标准分析输出

内容分析固定拆成四步输出：

| 输出        | 目标           | 作用           |
| --------- | ------------ | ------------ |
| 内容分析无数据   | 先从内容本身做结构化判断 | 形成第一轮主观分析    |
| 内容分析数据修正后 | 结合数据重新判断     | 形成第二轮更稳的结论   |
| 修正对比      | 对比修正前后差异     | 找出误判点与高价值修正点 |
| 内容特征提取    | 抽出可复用特征      | 进入后续汇总、选题和生产 |

- `内容分析无数据` 负责建立第一轮解释
- `内容分析数据修正后` 负责建立第二轮验证
- `修正对比` 负责帮助方法论自我校准
- `内容特征提取` 负责把单篇分析变成资产

## 8. 标准分析顺序

讨论一篇内容时，按下面顺序推进：

| 步骤         | 目标                       | 输出      |
| ---------- | ------------------------ | ------- |
| 1. 先判内容类别  | 明确这篇主要用什么方式交付价值          | 内容类别判断  |
| 2. 从表现层进入  | 看用户最终看到什么                | 表现层观察   |
| 3. 拆动作层    | 看具体用了哪些写法和结构             | 动作层判断   |
| 4. 解释机制层   | 解释为什么这些动作能起作用            | 机制层判断   |
| 5. 回到策略层   | 判断用了什么内容类别、媒介形式和主目标侧重    | 策略层判断   |
| 6. 反推出内核层  | 判断写给谁、解决什么、承诺什么、想让用户相信什么 | 内核层判断   |
| 7. 做正向校验   | 检查内核层能否正向解释策略、机制、动作和表现   | 一致性判断   |
| 8. 判断内容质量  | 看进入、持续、获得、沉淀是否成立         | 质量判断    |
| 9. 用数据修正   | 看哪些判断需要验证或推翻             | 数据修正后判断 |
| 10. 做修正对比  | 找出误判与新增洞见                | 修正对比    |

- `内容分析的方法顺序是：表现层 -> 动作层 -> 机制层 -> 策略层 -> 内核层 -> 正向校验，再用数据做修正，并最终提取可复用特征。`
