# 内容基础数据获取流程

## 1. 全局说明

在对话中默认持续暴露当前进度。所有内容都使用中文

展示规则：

- 使用勾选清单展示流程状态
- 统一格式为：`步骤名：当前状态或结论`
- 默认只展示当前所处步骤、当前状态、卡点和下一步动作
- 不原样暴露全部内部推理过程

当前版本只处理：

- 用户在对话中直接提供 `小红书 / 抖音 / B站` 的单条视频链接

示例：

- `[`**✓**`] 检查链接：已识别为小红书链接`
- `[`**✓**`] 获取数据：已通过 Chrome DevTools MCP 拿到基础 JSON`
- `[ ] 生成文案：正在提取视频文案`

<br />

## 2. 总流程说明

1. 检查链接
2. 获取基础结构化数据
3. 检查结果与判断重复
4. 回写基础结构化数据
5. 获取视频文案
6. 获取原文案总结
7. 回写路径并完成

<br />

## 3. 具体流程说明

### 3.1 检查链接

固定检查：

- 链接是否可识别
- 平台是否属于 `小红书 / 抖音 / B站`

如果失败，停止本流程，并在对话中直接告知用户：

- 链接无法识别
- 当前平台暂不支持

### 3.2 获取基础结构化数据

当前取数方案只保留两种：

1. `Chrome DevTools MCP`
   - 当前默认执行方案
2. `API付费`
   - 当前只写 `JustOneAPI`
   - 只写已经跑通的链路

执行前先固定判断：

1. 先判断当前对话是否可调用 `Chrome DevTools MCP`
2. 再读取 [`本地配置.env`](file:///Users/tanxiao/Desktop/AI自媒体系统/本地配置.env) 中的 `JUSTONEAPI_TOKEN`
3. 如果 `Chrome DevTools MCP` 可用，固定优先使用 `Chrome DevTools MCP`
4. 如果 `Chrome DevTools MCP` 不可用，但 `JUSTONEAPI_TOKEN` 已填写，固定改用 `JustOneAPI`
5. 如果两个方案都不可用，停止本流程，并在对话中直接告知用户当前无法继续

如果两个方案都不可用，固定告知用户：

- 当前无法获取基础结构化数据
- 当前可用方案只有 `Chrome DevTools MCP` 和 `JustOneAPI`
- `Chrome DevTools MCP` 安装文档：[查看文档](https://ecnqmxtwmpe9.feishu.cn/wiki/QSbPwOWpbiabBgkzddkc0ui5nI0?from=from_copylink)
- `JustOneAPI` 配置文档：[查看文档](https://ecnqmxtwmpe9.feishu.cn/wiki/QSbPwOWpbiabBgkzddkc0ui5nI0?from=from_copylink)

如果当前选中 `Chrome DevTools MCP`，动作固定如下：

1. 连接本机 `Chrome`
2. 新开标签页
3. 打开用户提供的链接
4. 等待页面加载完成
5. 优先读取页面结构化状态
6. 如果结构化状态不完整，再补读 DOM
7. 如果 DOM 仍不完整，再补读 Network
8. 输出一份标准 JSON

如果当前选中 `JustOneAPI`，动作固定如下：

1. 读取 [`本地配置.env`](file:///Users/tanxiao/Desktop/AI自媒体系统/本地配置.env) 中的 `JUSTONEAPI_TOKEN`
2. 固定使用 `https://api.justoneapi.com`
3. 先识别当前链接属于 `小红书 / 抖音 / B站`
4. 先调用当前平台主接口
5. 如果主接口失败，继续按当前平台文档中的同类接口继续尝试，直到成功
6. 如果全部失败，停止本流程，并在对话中直接告知用户当前平台的 `JustOneAPI` 接口全部失败
7. 把成功返回的结果映射成标准 JSON

`小红书` 固定动作如下：

1. 先从链接中提取 `noteId`
2. 先调用 `/api/xiaohongshu/get-note-detail/v5`
3. 如果失败，继续按下面顺序尝试：
   - `/api/xiaohongshu/get-note-detail/v4`
   - `/api/xiaohongshu/get-note-detail/v2`
   - `/api/xiaohongshu/get-note-detail/v1`
4. 从成功返回结果中读取：
   - `user.user_id`
   - `title`
   - `user.nick_name`
   - `image_list[0].url`
   - `video.media.stream.h264[0].master_url`
   - `interact_info`
   - `time`
5. 映射成标准 JSON

`抖音` 固定动作如下：

1. 先调用 `/api/douyin/share-url-transfer/v1`
2. 从返回结果中提取 `videoId`
3. 再调用 `/api/douyin/get-video-detail/v2`
4. 如果详情接口失败，继续按当前抖音文档中的同类详情接口继续尝试，直到成功
5. 从成功返回结果中读取：
   - `author.sec_uid`
   - 如果没有 `author.sec_uid`，就改用 `author.uid`
   - `caption`
   - `author.nickname`
   - `statistics`
   - `create_time`
6. 映射成标准 JSON

`B站` 固定动作如下：

1. 先从链接中提取 `bvid`
2. 直接调用 `/api/bilibili/get-video-detail/v2`
3. 如果详情接口失败，继续按当前 B站 文档中的同类详情接口继续尝试，直到成功
4. 从成功返回结果中读取：
   - `videoData.owner.mid`
   - `videoData.title`
   - `videoData.owner.name`
   - `videoData.pic`
   - `videoData.stat`
   - `videoData.pubdate`
   - `dash_info.dash.video[0].base_url`
5. 映射成标准 JSON

标准 JSON 固定包含：

- `平台`
- `账号ID`
- `标题`
- `账号昵称`
- `封面图原链接`
- `下载笔记原链接`
- `媒介形式`
- `点赞数`
- `收藏数`
- `分享数`
- `评论数`
- `发布时间`
- `笔记链接`

### 3.3 检查结果与判断重复

固定读取：

- `07-记录表/内容库.csv`
- 如果需要同步账号级内容列表，再读取 `07-记录表/账号库.csv`

固定检查：

- JSON 中当前已拿到哪些字段
- 当前 `笔记链接` 是否已存在于 `内容库.csv`

重复判断规则固定为：

- 只用 `笔记链接` 判断重复
- `内容库.csv` 中如果已存在完全相同的 `笔记链接`，就视为重复

如果当前字段缺失，固定动作如下：

1. 先回到 `3.2 获取基础结构化数据`
2. 如果当前正在用 `Chrome DevTools MCP`，就补读 DOM 或 Network
3. 如果当前正在用 `JustOneAPI`，就继续尝试同平台别的接口
4. 如果两个方案都已经用完，仍然缺字段，就停止本流程，并在对话中直接告知用户缺失字段

如果失败，停止本流程，并在对话中直接告知用户：

- 哪些字段缺失
- 当前内容已存在，并给出已存在的 `内容ID`

### 3.4 回写基础结构化数据

固定读取：

- `07-记录表/内容库.csv`
- 如果需要同步账号级内容列表，再读取 `07-记录表/账号库.csv`

固定生成：

- `内容ID`
- 内容目录
- `封面图路径`

生成规则固定如下：

1. 读取 `内容库.csv` 中现有最大 `内容ID`，生成下一个 `内容ID`
2. 创建目录：
   - `09-对标内容/<内容ID>-<内容标题前10个字>/`
3. 如果当前已有 `封面图原链接`，就下载封面图
4. 固定保存到：
   - `09-对标内容/<内容ID>-<内容标题前10个字>/封面图.png`
5. 生成 `封面图路径`

固定写入 `内容库.csv` 的字段：

- `内容ID`
- `平台`
- `账号ID`
- `账号昵称`
- `标题`
- `封面图原链接`
- `封面图路径`
- `下载笔记原链接`
- `媒介形式`（当前表头迁移前沿用 `内容类型` 旧字段）
- `点赞数`
- `收藏数`
- `分享数`
- `评论数`
- `核心互动数`
- `发布时间`
- `发布时间区间`
- `笔记链接`
- `备注`

如果需要同步账号级内容列表，固定动作如下：

1. 在 `账号库.csv` 中按 `平台 + 账号ID` 查找账号
2. 如果找到，并且该行存在 `内容列表路径`，再读取并回写对应 `内容列表.csv`
3. 如果找不到，或没有 `内容列表路径`，就跳过账号级内容列表回写

写入规则固定如下：

1. `账号ID` 固定写平台账号ID，不再生成内部自增账号ID
2. `账号昵称` 只作为展示字段，不作为账号唯一识别字段
3. 账号唯一识别固定使用 `平台 + 账号ID`
4. 如果 `封面图原链接` 已有值，就直接下载并保存为 `封面图.png`
5. 如果封面图下载失败，`封面图路径` 保留为空，并在对话中明确告知用户
6. `核心互动数 = 点赞数 + 收藏数 + 评论数`
7. `发布时间区间` 按发布时间所在小时生成
8. 当前拿不到的字段保留为空
9. 空字段必须在对话中明确告知用户

### 3.5 获取视频文案

目标文件：

- `09-对标内容/<内容ID>-<内容标题前10个字>/视频文案.md`

先判断：

- `媒介形式` 是否为 `视频`

如果不是视频，停止本流程，并在对话中直接告知用户当前版本只处理视频内容。

平台规则固定如下：

- `B站`
  - 优先取字幕
  - 没有字幕再走 ASR
- `抖音`
  - 直接走 ASR
- `小红书`
  - 直接走 ASR

`B站` 字幕获取方案固定如下：

1. 如果当前基础结构化数据来源是 `JustOneAPI`，直接复用结果中的 `bvid`、`aid`、`cid`
2. 如果当前基础结构化数据来源是 `Chrome DevTools MCP`，从页面结构化数据中读取 `bvid`、`aid`、`cid`
3. 如果当前基础结构化数据来源是 `JustOneAPI`，调用 `/api/bilibili/get-video-caption/v2`
4. 如果当前基础结构化数据来源是 `Chrome DevTools MCP`，调用播放器字幕接口
5. 从字幕列表中拿到 `subtitle_url`
6. 下载字幕 JSON
7. 合并所有字幕文本
8. 写入 `视频文案.md`

如果 `B站` 没有字幕，或字幕获取失败，再走 ASR。

ASR 执行动作固定如下：

1. 直接复用基础结构化数据中的 `下载笔记原链接`
2. 读取 [`本地配置.env`](file:///Users/tanxiao/Desktop/AI自媒体系统/本地配置.env) 中的阿里云百炼配置
3. 优先调用 `qwen3-asr-flash-filetrans`
4. 如果主方案失败，再切换到 `paraformer-v2`
5. 从返回结果中提取纯正文文案
6. 写入 `视频文案.md`

如果失败，停止本流程，并在对话中直接告知用户：

- `下载笔记原链接` 不可用
- `qwen3-asr-flash-filetrans` 和 `paraformer-v2` 都失败
- ASR 返回为空

输出要求：

- `视频文案.md` 只保留正文文案
- 当前版本不保留时间戳

### 3.6 获取原文案总结

目标文件：

- `09-对标内容/<内容ID>-<内容标题前10个字>/原文案总结.md`

生成输入固定为：

- `视频文案.md`
- `标题`

输出要求固定如下：

- 生成 `原文案总结.md`
- 内容只保留总结结果，不保留过程
- 固定包含：
  - `内容主题`
  - `开头钩子`
  - `核心观点`
  - `结构拆解`
  - `结尾动作`

### 3.7 回写路径并完成

回写到：

- `07-记录表/内容库.csv`
- 如果 `账号库.csv` 中已存在当前 `平台 + 账号ID` 对应的 `内容列表路径`，再回写该文件

固定写入：

- `封面图路径`
- `视频文案路径`
- `原文案总结路径`

满足下面条件，就算完成：

1. `内容库.csv` 已写入当前内容
2. 如果当前账号已在 `账号库.csv` 中存在，并且有 `内容列表路径`，该文件已同步当前内容
3. `视频文案.md` 已生成
4. `原文案总结.md` 已生成

完成后，进入：

- `03-执行流程/内容分析流程.md`
