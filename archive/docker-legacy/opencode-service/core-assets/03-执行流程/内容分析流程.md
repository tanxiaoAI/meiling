# 内容分析流程

## 1. 全局说明

在对话中默认持续暴露当前进度。所有内容都使用中文。

展示规则：

- 使用勾选清单展示流程状态
- 统一格式为：`步骤名：当前状态或结论`
- 默认只展示当前所处步骤、当前状态、卡点和下一步动作
- 不原样暴露全部内部推理过程
- 若本轮为 `局部重做`，进度展示优先围绕本轮修改点展开
- 一个重步骤只做一次独立生成，不把多个重任务塞进同一轮
- 一个阶段完成后，下一阶段不默认继承上一阶段的全部材料
- 执行器应裁切到当前阶段明确列出的必需输入，再继续执行

示例：

- `[`**✓**`] 判断起点：本轮从无数据分析开始`
- `[`**✓**`] 生成初判：已写入内部初判文件`
- `[ ] 组装用户版：正在生成内容分析.md`

<br />

## 2. 总流程说明

1. 前置步骤
   - 先进入 `3.1 判断分析起点`
   - 再进入 `3.2 检查资料与异常处理`
   - 若缺基础资料，先转去执行 `03-执行流程/内容基础数据获取流程.md`
2. 分阶段执行
   - 第 1 阶段进入 `3.3 生成内部初判`
   - 第 2 阶段进入 `3.4 生成内部修正`
   - 第 3 阶段进入 `3.5 生成用户版内容分析`
   - 第 4 阶段进入 `3.6 提取内容特征`
   - 如有需要，再进入 `3.7 提取修正对比`
3. 收尾步骤
   - 完成后进入 `3.8 自动录入内容特征库`
   - 再进入 `3.9 对话中反馈用户`
   - 最后进入 `3.10 回写内容库`

<br />

## 3. 具体流程说明

### 3.1 判断分析起点

用于判断本轮应该从哪一步开始。

判断依据只有两类：

- `用户对话意图`
- `关键文件是否存在且可读`

固定先读取：

- `07-记录表/内容库.csv`

先在内部明确：

- 本轮分析的是哪个 `内容ID`
- 用户想直接做哪一步
- 当前已经完成到哪一步
- 本轮结束后要落到哪些文件

关键字段固定读取：

- `内容ID`
- `标题`
- `媒介形式`（当前内容库表头迁移前沿用 `内容类型` 旧字段）
- `点赞数`
- `收藏数`
- `分享数`
- `评论数`
- `核心互动数`
- `数据水平`
- `视频文案路径`
- `内容分析初判路径`
- `内容分析修正路径`
- `内容分析路径`
- `修正对比路径`
- `内容特征提取路径`

判断规则：

1. 如果当前对话只给了内容链接、Excel、飞书表格或其他原始来源，还没有定位到 `内容库.csv` 当前行
   - 不进入本流程
   - 先执行 `03-执行流程/内容基础数据获取流程.md`
2. 如果 `视频文案.md` 缺失或不可读
   - 不进入本流程
   - 先执行 `03-执行流程/内容基础数据获取流程.md`
3. 如果用户明确要更新 `内容分析.md`
   - 先判断内部初判和内部修正是否已经存在
   - 缺哪一步，就从哪一步开始补
4. 如果用户明确要做 `修正对比`
   - 且 `内容分析初判.md` 与 `内容分析修正.md` 都已存在，则从 `修正对比` 开始
   - 否则回退到上游缺失步骤
5. 如果用户明确要做 `内容特征提取`
   - 且 `内容分析初判.md` 与 `内容分析修正.md` 都已存在，则从 `内容特征提取` 开始
   - 否则回退到上游缺失步骤
6. 如果用户没有明确指定步骤
   - 默认从当前最靠前的缺失步骤开始

默认回退顺序：

- 缺 `内容分析初判.md`，就从 `生成内部初判` 开始
- 不缺 `内容分析初判.md` 但缺 `内容分析修正.md`，就从 `生成内部修正` 开始
- 前两者都有但缺 `内容分析.md`，就从 `生成用户版内容分析` 开始
- `内容分析.md` 已有但缺 `内容特征提取.md`，就从 `提取内容特征` 开始
- 前面都有且用户明确要求，再做 `提取修正对比`

### 3.2 检查资料与异常处理

这一步不再重复读取 `内容库.csv` 当前行，只检查 `3.1` 已经定位到的结果能不能支撑本轮继续。

固定检查：

- `视频文案路径` 是否已填写
- `视频文案.md` 是否存在且可读
- 本轮起点依赖的上游文件是否存在且可读

异常处理规则：

1. `视频文案.md` 缺失或不可用
   - 先执行 `03-执行流程/内容基础数据获取流程.md`
   - 执行完成后回到本流程
   - 在对话中明确告知用户：本轮额外执行了 `内容基础数据获取流程`
2. 本轮起点依赖的上游文件缺失
   - 不硬跳当前步骤
   - 直接回退到最近的缺失步骤
3. 没有缺资料
   - 直接进入本轮起点对应阶段

### 3.3 生成内部初判

读取输入：

- `02-业务方法论/内容分析方法论.md`
- `视频文案.md`
- `标题`
- `媒介形式`

本步目标：

- 对内容做第一轮无数据判断
- 形成后续修正的原始判断底稿

调用：

- `04-提示词/内容分析-无数据提示词.md`

保存到：

- `09-对标内容/<内容ID>/内容分析初判.md`

### 3.4 生成内部修正

读取输入：

- `02-业务方法论/内容分析方法论.md`
- `内容分析初判.md`
- `标题`
- `点赞数`
- `收藏数`
- `分享数`
- `评论数`
- `核心互动数`
- `数据水平`

本步目标：

- 基于数据对第一轮判断做修正
- 保留哪些判断成立、哪些判断被推翻、为什么被修正

调用：

- `04-提示词/内容分析-数据修正后提示词.md`

保存到：

- `09-对标内容/<内容ID>/内容分析修正.md`

### 3.5 生成用户版内容分析

读取输入：

- `内容分析初判.md`
- `内容分析修正.md`
- `标题`
- `平台`
- `媒介形式`
- `点赞数`
- `收藏数`
- `分享数`
- `评论数`
- `核心互动数`
- `数据水平`

本步目标：

- 生成给用户看的正式版 `内容分析.md`
- 把初判和修正结果整合成一份连续可读的文档
- 在文档中保留关键修正链路，但不展开全部内部过程

文档结构固定包含：

- `基础信息`
- `第一轮判断`
- `第二轮修正`
- `修正汇总`
- `最终结论`
- `单篇内容启发`

组装要求：

- 对同一个判断项，尽量写成 `原判断 -> 修正后 -> 为什么`
- 用户版文档只保留关键变化，不展开全部中间推理
- 单篇内容启发并入 `内容分析.md`，不再默认单独生成文件

保存到：

- `09-对标内容/<内容ID>/内容分析.md`

### 3.6 提取内容特征

读取输入：

- `内容分析初判.md`
- `内容分析修正.md`
- `内容分析.md`
- `标题`
- `媒介形式`
- `数据水平`

本步目标：

- 提取这篇内容最值得沉淀的结构化特征
- 同时标记哪些特征成立、哪些特征被修正、哪些特征不成立

调用：

- `04-提示词/内容分析-内容特征提取提示词.md`

保存到：

- `09-对标内容/<内容ID>/内容特征提取.md`

### 3.7 提取修正对比

读取输入：

- `内容分析初判.md`
- `内容分析修正.md`

本步目标：

- 为后续调整提示词和方法论提炼修正经验
- 默认按需执行，不是每次必做

调用：

- `04-提示词/内容分析-修正对比提示词.md`

保存到：

- `09-对标内容/<内容ID>/修正对比.md`

### 3.8 自动录入内容特征库

读取输入：

- `07-记录表/内容特征库.csv`
- `09-对标内容/<内容ID>/内容特征提取.md`
- `07-记录表/内容库.csv` 当前内容行
- `02-业务方法论/内容特征词典.md`

本步目标：

- 不是再次分析内容，而是把 `内容特征提取.md` 拆成多条记录并写入 `内容特征库.csv`
- 一行代表 `一个特征在一篇内容中的一次出现`

组装输入：

- `内容库.csv` 当前内容的基础字段
- 当前内容的 `内容特征提取.md`
- `02-业务方法论/内容特征词典.md`

调用：

- `04-提示词/内容特征自动录入提示词.md`

写入规则：

- `记录ID`
  - 自动生成
  - 建议格式：`特征记录001`
- `样本来源`
  - 当前对标内容默认写 `对标`
- `内容ID`
  - 来自 `内容库.csv`
- `账号ID`
  - 来自 `内容库.csv`
  - 当前表示平台账号ID
- `标题`
  - 来自 `内容库.csv`
- `数据水平分组`
  - 来自 `内容特征提取.md` 或 `内容库.csv`
- `媒介形式`
  - 优先来自 `内容库.csv`
  - 如果当前表头仍沿用旧字段，则读取旧字段 `内容类型`
- `所属层级`
  - 由字段所属模块自动判断
- `特征小类`
  - 由字段名自动判断
- `特征值`
  - 写入该字段在本篇内容中的具体内容
- `标准标签`
  - 优先使用 `02-业务方法论/内容特征词典.md` 中已有标签
- `是否主特征`
  - 默认先写 `否`
  - 只有在 `内容特征提取.md` 明确体现为核心成立点时才写 `是`
- `验证状态`
  - 根据字段后附带的 `已验证 / 部分验证 / 未验证` 自动写入
  - 如果原文没有明确写，默认写 `未明确`
- `我方验证状态`
  - 当前对标内容默认写 `未验证`
- `是否被修正`
  - 如果该字段出现在 `被修正点` 中，写 `是`
  - 否则写 `否`
- `修正方向`
  - 根据 `第一轮高估点 / 第一轮低估点` 自动写 `高估 / 低估 / 无修正`
- `证据来源`
  - 默认写对应字段名，例如 `标题标签`、`主要吸引机制`、`命题`
- `内容特征提取路径`
  - 当前内容的 `内容特征提取.md` 路径
- `备注`
  - 默认留空

去重规则：

- 同一个 `内容ID`
- 同一个 `所属层级`
- 同一个 `特征小类`
- 同一个 `标准标签`

如果已经存在，就不要重复追加。

如果用户明确要求重录，则先以当前内容为范围覆盖旧记录，再重新写入。

词典校验规则：

- 如果 `标准标签` 能在 `02-业务方法论/内容特征词典.md` 中找到，直接写入
- 如果找不到：
  - 先写 `待定标签`
  - 把具体内容写进 `特征值`
  - 在 `备注` 中标记 `待补词典`

结果处理：

- 将拆分后的多条特征记录追加写入 `07-记录表/内容特征库.csv`
- 在对话中告知用户本次共新增多少条特征记录
- 如果出现大量 `待定标签`，提醒用户后续统一校准 `02-业务方法论/内容特征词典.md`

### 3.9 对话中反馈用户

完成本轮步骤后，在对话中单独告诉用户：

- 本轮完成到了哪个阶段
- 当前还缺不缺资料
- 如果继续下一步，下一步要读取什么
- 当前是否已经生成 `内容分析.md`
- 如果发现明显误判，最该回看的是什么阶段

### 3.10 回写内容库

完成后回写 `07-记录表/内容库.csv` 对应内容行的以下字段：

- `内容分析初判路径`
- `内容分析修正路径`
- `内容分析路径`
- `修正对比路径`
- `内容特征提取路径`

如果路径本来已存在，则保持不变。

备注字段可以按需要补一句当前进度，例如：

- `已完成内容分析初判`
- `已完成内容分析修正`
- `已完成内容分析`
- `已完成内容特征提取`
- `已完成修正对比`

## 4. 默认边界

单篇内容分析默认：

- 对用户默认只交付 `内容分析.md`
- 不额外生成 `内容分析报告.md`
- 不额外生成 `单篇内容总结.md`

默认内部标准结果如下：

- `内容分析初判.md`
- `内容分析修正.md`
- `内容分析.md`
- `内容特征提取.md`

其中：

- `内容分析.md` 是用户版正式结果
- `内容分析初判.md` 与 `内容分析修正.md` 是内部中间状态，用于保证修正链路不丢
- `修正对比.md` 默认按需生成，不是每次必做

需要明确：

- 批量的特征汇总、特征对比、特征组合判断，不在本流程中处理
- 这些工作统一交给 `03-执行流程/内容特征汇总分析流程.md`
- 不允许在一个重步骤里同时要求模型完成 `初判 + 修正 + 用户版组装 + 特征提取`
