# 自媒体模式分析流程

## 1. 全局说明

在对话中默认持续暴露当前进度。所有内容都使用中文

展示规则：

- 使用勾选清单展示流程状态
- 统一格式为：`步骤名：当前状态或结论`
- 默认只展示当前所处步骤、当前状态、卡点和下一步动作
- 不原样暴露全部内部推理过程
- 若本轮为`局部修改`，进度展示优先围绕本轮修改点展开，不展开为完整全局流程

示例：

- `[`**✓**`] 读取资料：已读取方法论与我方资料`
- `[`**✓**`] 检查信息：已判断当前更适合继续讨论和确认`
- `[ ] 对话讨论：正在围绕本轮关键问题继续讨论`

<br />

## 2. 总流程说明

1. 前置步骤
   - 先进入 `3.1 读取资料`
   - 再进入 `3.2 检查信息`
2. 中间循环
   - 前置步骤完成后，进入 `3.3 对话讨论`
   - 每轮对话后，进入 `3.4 确认是否成稿`
   - 若 `3.4 确认是否成稿` 判断当前还不适合询问用户是否成稿，回到 `3.3 对话讨论`
   - 若 `3.4 确认是否成稿` 中用户还想继续讨论、补充或修正，也回到 `3.3 对话讨论`
3. 成稿步骤
   - 只有当 `3.4 确认是否成稿` 判断已经可以询问用户是否成稿，且用户明确确认时，才跳出循环
   - 若本轮为 `重写`，依次进入 `3.5 整理摘要`、`3.6 组装输入并调用成稿提示词`、`3.7 保存结果`
   - 若本轮为 `局部修改`，依次进入 `3.5 整理摘要`、`3.6 组装输入并调用成稿提示词`、`3.7 保存结果`
4. 成稿后分流
   - 保存完成后，进入 `3.8 成稿后分流`
   - 若用户认可这版，本轮结束
   - 若仍在同一对话中继续补充、追问、修正或提出新的正式修改意见，默认回到 `3.3 对话讨论`

<br />

## 3. 具体流程说明

### 3.1 读取资料

固定读取：

- `02-业务方法论/自媒体模式方法论.md`
- `05-我方资料/我方自媒体模式.md`
- `05-我方资料/我方调整候选池.md`

说明：

- 默认创建的文件为空白，照常读取

<br />

### 3.2 检查信息

按 `02-业务方法论/自媒体模式方法论.md` 的核心要素逐项检查当前状态。

这里直接引用方法论中的核心要素，但在这一步不单独检查 `自媒体模式总结`。

每一组只判断 3 件事：

- `是否已有明确结论`
- `是否存在冲突或摇摆`
- `当前更适合补缺，还是更适合讨论和确认`

说明：

- 这一步是内部执行步骤，不属于最终交付文档
- 不要把这一步原样输出到 `我方自媒体模式.md`
- 这一步只负责判断当前清楚到什么程度，以及 `3.3 对话讨论` 应该以什么模式推进

### 3.3 对话讨论

这一阶段是本轮用户交互主节点。

执行规则：

- 先检查自媒体模式核心要素
- 如果发现 `模式层承接` 已经清楚，继续自媒体模式讨论
- 如果 `模式层承接` 不清楚，再查看 `05-我方资料/我方商业模式.md`
- 如果商业模式里的相关内容已经够用，就直接提炼成 `模式层承接`
- 如果商业模式里的相关内容也不够，就询问用户二选一：调用 `/commercial-model-analysis` 先补清商业模式，再回到当前流程；或直接在自媒体模式中讨论 `模式层承接`
- 每轮只围绕当前最关键的 1 个问题继续讨论
- 默认按方法论顺序推进
- 如果当前已有明确修改范围，优先围绕本轮修改点，以及被直接连带影响的部分继续讨论
- 如果用户回答已经足够，不再机械补问
- 如果用户明确表示某部分暂时未定，就允许保留边界，不要强行补齐
- 如果讨论开始扩散到本轮不打算修改的部分，优先收住，不继续发散

### 3.4 确认是否成稿

这一阶段分两步处理：先内部判断当前是否已经适合询问用户要不要进入成稿；如果已经适合，再在对话中明确询问用户是否现在进入成稿。

内部判断至少满足下面几点：

- 本轮核心问题已经讨论清楚
- 当前模式层承接、账号层、内容层和当前边界已有可写结论，或本轮修改点及其直接连带影响已经闭环
- 剩余未确认内容不会影响主体结构成立

在进入成稿前，还需要判断本轮应按 `重写` 还是 `局部修改` 处理。

判断规则：

- `我方自媒体模式.md` 当前为空白、只有零碎说明、或现有内容不足以稳定承接旧版：按 `重写`
- 本轮只改少数几个明确章节，且未受影响部分希望尽量保留原文：按 `局部修改`
- 本轮修改点已经影响模式层承接、账号主心智、内容主线或整体结构：按 `重写`

必须先在对话中和用户明确确认：

- 本轮目标是否已经说清楚
- 是否现在就生成或修改 `05-我方资料/我方自媒体模式.md`

只有当用户明确表达下面这类意思时，才能继续：

- `可以生成`
- `按这个修改`
- `先出一版`
- `可以进入成稿`
- 其他等价确认

如果当前还不适合询问用户是否成稿，或用户还在补充、摇摆、比较方案或继续讨论，则继续留在循环中。

### 3.5 整理摘要

先基于之前所有的对话，整理一份结构化摘要，固定包含：

- `本轮任务`
- `已确认结论`
- `本轮修改范围`（仅在`局部修改`时需要）
- `模式层承接`
- `账号层`
- `内容层`
- `当前边界`
- `与旧版相比的主要变化`
- `仍待确认的问题`

规则：

- 以已确认内容为主
- 口语化讨论要收束成正式判断
- 明显未确认的部分要保留不确定性，不要假装已经确定
- 若旧版 `我方自媒体模式.md` 与本次明确确认的结论冲突，以本次结论为准
- 若本轮为`局部修改`，必须明确写出 `本轮修改范围`
- `05-我方资料/我方调整候选池.md` 只用于讨论阶段存放候选内容；凡是本轮最终确认采用的内容，必须先吸收到 `本轮结构化摘要`，后续成稿阶段不再单独传候选池

### 3.6 组装输入并调用成稿提示词

根据 `3.4 确认是否成稿` 的判断，按固定规则分流：

#### 1. 重写

组装输入顺序：

1. `04-提示词/自媒体模式成稿提示词.md`
2. `3.5 整理摘要` 生成的 `本轮结构化摘要`

#### 2. 局部修改

组装输入顺序：

1. `04-提示词/自媒体模式局部更新提示词.md`
2. `05-我方资料/我方自媒体模式.md` 的完整旧版正文
3. `3.5 整理摘要` 生成的 `本轮结构化摘要`

### 3.7 保存结果

先将成稿输出保存到：

- `05-我方资料/我方自媒体模式.md`

保存要求：

- 直接保存正式正文
- 不写输入检查过程
- 不写追问过程
- 不写“以下是”“建议如下”“供参考”之类的提示语

保存 `我方自媒体模式.md` 后，立即基于该文档生成并保存：

- `05-我方资料/我方当前概要.md`

生成规则：

- 输入只使用最新保存的 `05-我方资料/我方自媒体模式.md`
- `我方当前概要.md` 是 `我方自媒体模式.md` 的压缩调用版，不重新分析，不补新判断
- 只保留后续流程最需要的当前结论，不写推导过程，不写解释性前言
- 各部分都写短，优先用 2 到 4 条短条目
- 结构固定为：
  1. `当前账号定位`
  2. `当前吸引对象`
  3. `当前成交对象`
  4. `当前前台承接`
  5. `当前内容主线`
  6. `当前信任来源`
  7. `当前差异化`
  8. `当前边界`
  9. `当前验证重点`

### 3.8 成稿后分流

成稿后，在对话里单独完成这一步：

- 请用户确认这版是否成立

规则：

- `本轮结束`：用户确认这版成立，没有新的正式修改要求
- `回到循环`：仍在同一对话中继续讨论，默认回到 `3.3 对话讨论`；必要时可先内部重做 `3.2 检查信息`
