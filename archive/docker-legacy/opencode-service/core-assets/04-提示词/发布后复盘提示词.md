# 发布后复盘提示词

你的任务是根据已提供的原始选题定稿、最终终稿、发布结果和必要的验证参考，输出一份本次内容发布后的复盘结论。

## 分析原则

- 先看原任务，再看最终结果，不要跳过预期直接评价结果
- 复盘的重点不是重复看数，而是解释：这次为什么会这样
- 先找主因，再提建议，不要把所有可能性都写一遍
- 区分 `选题判断`、`内容兑现`、`平台放大`、`商业承接`
- 如果证据不足，只下弱结论，不要硬推强归因
- 复盘必须服务后续回写和下一轮生产

## 输出要求

- 直接输出正式正文，不写解释性前言
- 不写“以下是”“供参考”“建议如下”
- 不复述提示词
- 不重新生成脚本
- 不输出流程说明
- 结果用于保存到 `复盘总结.md`，并支撑后续回写

## 输出结构

按下面固定结构输出：

## 1. 复盘对象

写清：

- `选题ID`
- `我方内容ID`
- `选题名称`
- `内容标题`
- `发布日期`

## 2. 原始任务回看

写清：

- 这条内容原本主要服务谁
- 原本核心痛点是什么
- 原本收益承诺是什么
- 原本核心命题和切口是什么
- 这条内容原本承担的主要任务是什么

## 3. 最终结果判断

写清：

- `整体表现判断`：只能写 `好于预期 / 符合预期 / 低于预期`
- `判断依据`
- `结果概括`

## 4. 主要归因

围绕下面四个方向判断主因：

- `选题判断`
- `内容兑现`
- `平台放大`
- `商业承接`

要求：

- 明确哪一层是主因
- 其他层只在确有证据时补充

## 5. 最该保留的做法

- 只写当前最值得保留的 1 到 3 个点
- 说明为什么值得保留

## 6. 最该修正的问题

- 只写当前最需要修正的 1 到 3 个问题
- 每个问题都写清：
  - `问题是什么`
  - `主要影响什么`
  - `下一次怎么改`

## 7. 特征与组合验证

写清：

- `本次成立特征`
- `本次未成立特征`
- `本次成立组合`
- `本次未成立组合`
- `我方验证结论`

要求：

- 只写本轮最重要的验证结论
- 如果证据不足，明确写 `暂不形成高置信验证`

## 8. 是否需要系统回写

写清：

- 这次结论是否只影响这一条内容
- 是否需要回写到：
  - `选题库`
  - `我方内容库`
  - `内容特征库 / 内容特征组合库`
  - `我方调整候选池`

## 9. 一句话复盘结论

- 用一句话写清：这次最该带走的提醒是什么
