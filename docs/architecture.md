# AI 自媒体系统 SaaS - 架构设计文档

> 版本：v1.0  
> 日期：2026-06-09

## 1. 系统概述

AI 自媒体系统 SaaS 是一个将现有文件系统工作流产品化为 SaaS 服务的解决方案，采用"一客户一项目"的隔离架构，确保数据安全和核心资产保护。

### 1.1 核心目标

- 将本地工作流产品化为 Web 访问的 SaaS 服务
- 保护核心方法论、提示词和业务逻辑不暴露给客户
- 提供简单、标准化的客户开户和管理流程
- 最小化自研代码，优先使用成熟开源方案

### 1.2 技术选型

| 组件 | 技术选型 | 用途 |
|------|---------|------|
| 客户前端 | OpenCode Web | 客户工作界面 |
| 后台管理 | Strapi | 运营者管理系统 |
| 部署平台 | Zeabur | 服务托管和部署 |
| 数据库 | PostgreSQL 14 | 数据持久化 |
| 文件存储 | Zeabur Volume | 工作空间存储 |
| 冷归档 | Cloudflare R2 | 可选的冷数据归档 |

### 2.2 客户实例架构

每个客户拥有独立的 Zeabur 项目：

```
tenant-c001/
├── opencode-c001          # OpenCode 服务容器
│   ├── /workspace/        # 客户可见工作空间
│   │   ├── inputs/
│   │   ├── benchmark-accounts/
│   │   ├── benchmark-contents/
│   │   ├── outputs/
│   │   └── results/
│   ├── /opt/core-assets/  # 核心资产（隐藏）
│   │   ├── system/
│   │   ├── methodology/
│   │   ├── workflows/
│   │   ├── prompts/
│   │   └── skills/
│   └── /workspace-internal/  # 系统内部（隐藏）
│       ├── temp/
│       ├── cache/
│       └── logs/
├── postgres-c001          # PostgreSQL 数据库
└── workspace-c001         # Volume 存储
```

## 3. 数据流设计

### 3.1 客户使用流程

```
1. 客户登录
   ↓
2. 访问 OpenCode Web 界面
   ↓
3. 上传资料到 /workspace/inputs/
   ↓
4. 执行分析任务（调用核心 skills）
   ↓
5. 查看结果（在 outputs/ 和 results/）
   ↓
6. 下载生成的文件
```

### 3.2 任务执行流程

```
OpenCode Web
    ↓ (用户触发任务)
OpenCode Server
    ↓ (加载核心资产)
/opt/core-assets/
    ├── 读取方法论
    ├── 加载 prompt 模板
    └── 执行 skill 工作流
    ↓
AI 模型 API (Claude)
    ↓ (返回结果)
生成输出文件
    ↓
/workspace/outputs/
/workspace/results/
    ↓
客户查看和下载
```

### 3.3 数据隔离

**完全隔离**：
- 每个客户独立的 Zeabur 项目
- 独立的数据库实例
- 独立的 Volume 存储
- 独立的域名

**共享资源**（只读）：
- 核心资产内置在镜像中（每个容器独立副本）
- 系统配置和 skills

## 4. 安全设计

### 4.1 访问控制

#### 客户权限

| 路径 | 读取 | 写入 | 删除 |
|------|------|------|------|
| /workspace/inputs/ | ✓ | ✓ | ✓ |
| /workspace/benchmark-accounts/ | ✓ | ✗ | ✗ |
| /workspace/benchmark-contents/ | ✓ | ✗ | ✗ |
| /workspace/outputs/ | ✓ | ✗ | ✗ |
| /workspace/results/ | ✓ | ✗ | ✗ |
| /opt/core-assets/ | ✗ | ✗ | ✗ |
| /workspace-internal/ | ✗ | ✗ | ✗ |

#### 文件类型限制

禁止访问的文件类型：
- `.env`, `.key`, `.pem`, `.p12` - 敏感配置
- 包含 `secret`, `private`, `credential` 的文件
- `.git` 目录和版本控制文件

### 4.2 核心资产保护

**保护方式**：
1. 内置到 Docker 镜像的 `/opt/core-assets/`
2. 设置为只读权限（444/555）
3. 不映射到客户可见的文件树
4. OpenCode 配置隐藏该路径

**核心资产包括**：
- 01-系统层/
- 02-业务方法论/
- 03-执行流程/
- 04-提示词/
- .claude/skills/
- .trae/skills/

### 4.3 网络安全

- HTTPS 强制访问（Zeabur 自动提供）
- Cloudflare CDN 和 DDoS 防护
- 容器间网络隔离
- 数据库仅内部访问

### 4.4 身份认证

- OpenCode 服务级别的用户名/密码认证
- Strapi 后台的 RBAC 权限管理
- API Token 用于程序化访问

## 5. 扩展性设计

### 5.1 垂直扩展

**单客户实例扩展**：
- 增加 CPU 和内存配额
- 扩大 Volume 存储容量
- 升级数据库规格

### 5.2 水平扩展

**增加客户数量**：
- 创建新的 Zeabur 项目（tenant-cXXX）
- 使用自动化开户脚本
- 标准化的资源配置模板

### 5.3 性能优化

- 静态资源 CDN 缓存
- 数据库连接池
- 任务队列异步处理
- 文件缓存机制

## 6. 可靠性设计

### 6.1 数据备份

**自动备份**：
- Zeabur PostgreSQL 每日自动备份
- 保留 7 天备份历史

**手动备份**：
- 使用 `backup.sh` 脚本导出数据
- 包括数据库和 Volume 内容

### 6.2 监控和告警

**健康检查**：
- 容器级别健康检查端点
- Zeabur 平台自动监控
- 服务自动重启

**日志记录**：
- 应用日志记录到 `/workspace-internal/logs/`
- Zeabur 平台日志聚合
- 错误日志实时查看

### 6.3 灾难恢复

**RTO/RPO 目标**：
- RTO (恢复时间目标): < 1 小时
- RPO (恢复点目标): < 24 小时

**恢复流程**：
1. 创建新的客户项目
2. 恢复数据库备份
3. 恢复 Volume 数据
4. 重新部署服务
5. 验证服务可用性

| PostgreSQL | 基础实例 | $15 |

| 域名和 CDN | 基础套餐 | $5 |
| **合计** | | **~$42** |

### 7.2 运营成本

| 项目 | 月成本（USD） |
|------|--------------|
| Strapi 后台 | $25 |
| 开发和维护 | $500 |

### 7.3 定价建议

基于成本的定价模型：

- **基础版**：$199/月（成本 $42 + 利润 $157）

  - 1000 次 API 调用/月

- **专业版**：$499/月
  - 更高的配额和优先级
  - 5000 次 API 调用/月

- **企业版**：$999/月起
  - 定制化需求
  - 无限 API 调用

## 8. 技术债务和改进方向

### 8.1 当前限制

- 手动开户流程（需自动化）
- 无实时监控面板
- 配额管理较简单
- 无自动化告警

### 8.2 未来改进

**P1 优先级**：
- 自动化开户 API
- 配额用量实时追踪
- 任务队列和异步处理

**P2 优先级**：
- 客户自服务门户
- 详细的分析报表
- R2 冷归档集成
- 多区域部署

**P3 优先级**：
- 客户自定义 prompt
- API 开放平台
- 白标定制

## 9. 合规性

### 9.1 数据安全

- 数据加密传输（HTTPS）
- 数据库访问控制
- 定期安全审计
- 敏感信息脱敏

### 9.2 隐私保护

- 客户数据完全隔离
- 不跨客户共享数据
- 遵守 GDPR 和数据保护法规
- 明确的数据使用协议
